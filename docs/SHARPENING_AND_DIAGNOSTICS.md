# 锐化 / 振铃检测与诊断日志

v0.8.0 新增「锐化 / 振铃光晕 %」。适用于有效斜边和整卡多频率 USAF。模板缺少相应图案时仍显示灰色不可用；不会从普通纹理猜测一个锐化数值。

## 检测的含义

算法测量边缘附近超出两侧平台的亮、暗光晕，相对于局部明暗阶跃归一化。报告中保存 `sharpening_halo_pct`、`halo_overshoot_pct`、`halo_undershoot_pct` 和 `halo_noise_floor_pct`；最后一项是检测下限。

USAF 使用周期至少 40 个原像素的粗条纹，只测四个内部边缘，不使用整块图案外侧白底。相邻剖面采样须超过噪声检查，单个异常像素不作为光晕。每个单元、每个通道至少两个有效元素才汇总；竖线、横线可分别查看。单元记录中的锐化证据独立于分辨率交点，不会因为 CTF20 缺失就丢掉可用的低频边缘证据。

斜边使用已建立的 ESF 检查空间光晕，并保留既有 SFR 峰值增益提示。两类证据同时记录：SFR 增益不一定形成可测光晕，光晕也可能由光学振铃、图卡或处理流程共同引起。对齐后灰度经过软件插值，与原始 RGB 分别解释。

MUTEX 工程提示为：光晕 ≤2% 未见明显迹象，2–5% 建议留意，>5% 光晕明显。这些是项目建议，不是行业合格线。数值不是锐化概率，也不能反推出软件参数。未知输入曲线只测输入域响应；剪切可以隐藏光晕，因此 0% 不证明未经锐化。建议比较关闭锐化 / 自动对比度后的 RAW 或扫描结果。

选择该指标后可查看 RGB / 灰度热力图及代表性原像素剖面，悬停有说明；HTML、PDF 和 JSON/CSV 保存同一测量及评价。定义核对参考 [Imatest Sharpening](https://www.imatest.com/imaging/sharpening/)，本项目算法独立实现，不声称商业数值等价。

## 未测得不等于未识别

本版记录每个 USAF 单元的预测覆盖、匹配数、内点数及配准残差，区分图像范围外、边缘特征不足和配准不一致。完全在图像外的 ROI 返回零尺寸，不再产生负尺寸。

右侧说明和测量明细会列出缺失原因；`result.json` 的 `diagnostics_summary` 及所选项目汇总保留分类。例如：

- 局部拍摄没有包含某些星图：显示图像未覆盖 / 测量区域被裁切。
- USAF 模板没有适用斜边：MTF 项仍不可用，不能把 CTF 当 MTF。
- 单帧缺少焦位序列、没有物理标定或色块批次参考：保持相应前提要求。
- 条纹粘连、频率未覆盖交点、剪切或原像素不足：保留具体质量原因，不补零。

CTF / SFR 恰好落在有效采样的阈值上时，直接保留该实测频率；不再因为后面没有更低的样本而遗漏这个已知交点。

## 实时和错误日志

分析开始后，日志页显示实际阶段、耗时、定位进度、单元 CTF、RGB 位移、质量统计、锐化证据及导出阶段。进度来自真实作业；界面最多保留 4,000 行，避免长期分析拖慢窗口。

每次任务目录内保存：

| 文件 | 内容 |
| --- | --- |
| `analysis.log` | 可阅读的阶段与耗时 |
| `diagnostics.jsonl` | 带 UTC 时间、作业编号和详细字段的结构化记录 |
| `error.log` | 失败时的异常链、完整回溯、近期阶段、输入与配置、版本及内存 / 磁盘情况 |
| `native-crash.log` | 原生崩溃时可获得的 Python 线程栈；不替代系统崩溃转储 |

子进程异常退出还会记录十进制和 Windows 十六进制退出码。正常取消单独记录，不报告为崩溃。界面 / 瓦片读取异常另存用户日志目录。

同一输出目录再次运行时，上一轮日志移入 `.diagnostic-history/`，保留失败线索。关闭大图预览会取消过期的后台读取，避免关闭窗口后仍等待读取整张文件。

在「帮助 → 打开本次分析日志目录 / 打开界面错误日志目录」中访问。CLI 在每张图的输出文件夹保存同类文件，进度写入 stderr，结果输出仍保留在 stdout。

日志仅写本机，不自动上传。不会写入图像像素或模板矢量内容；配置中的密码、令牌等键会遮盖。日志仍含本机路径、文件名和设备 / 软件信息，分享前可自行检查。
